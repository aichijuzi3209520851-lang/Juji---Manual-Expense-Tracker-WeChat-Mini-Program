[P][Heading 2] 1.1 编写目的
[P][Normal] 本文档为橘记（Juji）微信小程序的软件界面设计书，旨在提供完整的界面视觉规范与交互行为准则，为UI实现、设计评审、开发验收提供统一的设计依据。
[P][Normal] 文档覆盖v1.1.0版本全部10个页面及共用设计系统，包含颜色体系、字体规范、组件规格、页面布局、交互行为、响应式适配等完整设计语言，确保产品在不同主题与设备下保持一致的视觉品质。

[P][Heading 1] 第2章 设计理念与品牌基调
[P][Heading 2] 2.1 设计理念
[P][Normal] 橘记的界面设计遵循以下四条核心原则，贯穿所有页面与组件的设计决策：
[P][Normal] 克制即美
[P][Normal] 界面元素精简、留白充足，拒绝信息过载。每一个视觉元素都必须承担明确的功能或情感职责，无装饰性冗余。通过限制颜色数量（单主色驱动）、统一圆角体系（40rpx主卡片）、克制阴影层次（三级Neumorphic），营造安静、整洁的记账氛围，让用户专注于数字本身。
[P][Normal] 温度优先
[P][Normal] 作为一款记账工具，橘记拒绝冰冷的表格与数字堆砌。通过品牌吉祥物「小橘」的4种动画（idle呼吸、wave招手、jump跳跃、heart爱心）提供情感陪伴，AI评论以温暖口吻解读消费趋势，主题色支持用户自定义（8色调色板+5个自命名），让每个人拥有专属的"记账空间"。
[P][Normal] 主题即品牌
[P][Normal] 采用单主色驱动的HSL推导机制，仅需用户提供一个hex色值，即可自动生成60+个CSS变量，包括渐变、阴影、表面色阶等派生token。这一机制确保橘记在任何主题色下都保持视觉一致性，同时让"换主题"成为用户粘性的来源。
[P][Normal] 动效有意义
[P][Normal] 所有动画服务于明确的交互意图：小橘idle动画（2.6s呼吸循环）暗示陪伴感，收支切换滑块（0.3s过渡）确认操作反馈，胶囊指示器（0.4s dot扩展）指示当前状态，引导页smoothUp（0.8s交错入场）营造仪式感。不存在纯装饰性动画，所有动效时长控制在0.3s-2.6s范围内。

[P][Normal] 「小橘」是橘记的品牌吉祥物，完全由纯CSS绘制的拟人化橘子形象，不依赖任何外部图片资源。固定配色方案确保跨主题一致性。

[P][Heading 2] 2.3 视觉风格定位
[P][Normal] 橘记的视觉风格定位在"小红书x Apple Wallet"的交汇处：兼具小红书的温暖质感与Apple Wallet的克制秩序。
[P][Normal] 核心视觉特征：
[P][List Bullet] 卡片式架构：
[P][Normal] 所有内容以卡片为单元组织，40rpx圆角+Neumorphic双侧阴影+白色/半透明背景，营造浮动层叠感。
[P][List Bullet] 渐变Hero区：
[P][Normal] 页面顶部使用primary->accent 135度跨色相渐变，作为品牌识别的核心视觉锚点。
[P][List Bullet] 大数字排版：
[P][Normal] 金额数字使用DIN Alternate字体，display级96rpx+font-weight 800，确保扫一眼即可获取关键信息。
[P][List Bullet] 毛玻璃质感：
[P][Normal] TabBar、弹窗等浮层使用backdrop-filter:blur(24rpx)+rgba半透明背景，与底层内容形成层次感。
[P][List Bullet] Neumorphic阴影：
[P][Normal] 采用双侧阴影系统（左上亮光+右下暗影），根据主题色着色（如薄荷主题阴影带绿色调），实现柔和的3D浮雕效果。

[P][Heading 1] 第3章 视觉设计规范（Design Token体系）
[P][Normal] 橘记采用Design Token（设计变量）体系，将所有视觉属性抽象为可复用的CSS自定义属性（Custom Properties），通过单一入口getThemeStyleString()注入inline-style，实现主题即时切换。
[P][Heading 2] 3.1 颜色体系
[P][Normal] 颜色体系基于单主色推导机制：用户选择一个主色（primary），系统自动推导出强调色（accent=primary色相+60度）、容器色、表面色阶、文字色阶等15个核心颜色token。

[P][Heading 2] 3.3 阴影体系（Neumorphic）

[P][Heading 2] 3.7 inline-style注入技术说明
[P][Normal] 微信小程序的CSS变量存在解析期定值问题：在page{}选择器中声明的CSS变量（如page{color-primary:#27c07d;}），会在WXSS解析时被立即计算并固化，后续通过父元素inline-style覆盖的var()引用不会动态响应变化。
[P][Normal] 解决方案：getThemeStyleString()函数在运行时计算所有60+个CSS变量的字面值（literal values），拼接为一个inline-style字符串（如"--color-primary:#27c07d;--gradient-hero:linear-gradient(135deg,#27c07d,#5ba4cb);..."），通过WXML的style="{{themeStyle}}"直接注入到页面最外层view元素上。这样所有子元素通过var()引用时，直接读取到的是已注入的字面值，而非page{}中的解析期定值。
[P][Normal] 派生token（渐变、阴影）必须在getThemeStyleString()中以字面值计算，不能使用var()引用其他变量——因为inline-style的var()解析顺序是层叠的，字面值注入可以保证正确的计算顺序。

[P][Heading 2] 7.3 主题切换交互
[P][Normal] 主题切换采用EventBus发布-订阅模式实现即时响应，无需重启小程序：

[P][Normal] 每个页面在onLoad注册监听、onUnload注销监听，确保无内存泄漏。

[P][Heading 1] 第8章 响应式适配与辅助功能
[P][Heading 2] 8.1 rpx响应式适配
[P][Normal] 橘记全面使用rpx（responsive pixel）作为尺寸单位，以750rpx为屏幕宽度基准。微信运行时会自动根据实际设备屏幕宽度进行等比缩放：在375pt逻辑宽度的设备（iPhone 6/7/8）上1rpx=0.5px，在414pt设备（iPhone 14 Pro Max）上1rpx约等于0.45px。
[P][Normal] 所有布局均采用flex/grid自适应，不使用固定px值。百分比宽度（如CTA按钮70%宽）配合max-width约束，确保在不同宽度的安卓设备上也不会过度拉伸。
[P][Heading 2] 8.2 深色模式
[P][Normal] 橘记的深色模式采用"深夜"主题（dark），而非跟随系统暗色模式。用户在主题设置页手动切换到dark主题即可启用。

[P][Heading 2] 8.3 无障碍辅助功能
[P][List Bullet] 触摸目标尺寸：
[P][Normal] 所有可交互元素的触摸热区不低于88rpx x 88rpx（约44pt），符合WCAG 2.1 AA标准的最小触摸目标尺寸要求。TabBar图标容器76rpx + 间距扩展至106rpx最小高度。
[P][List Bullet] 色彩对比度：
[P][Normal] 文字色--color-text（#0f1f17等深色）在--color-bg（#f2faf6等浅色）背景上的对比度均>7:1（AAA级）。次要文字--color-text-secondary在表面上的对比度>4.5:1（AA级）。主色上的文字--color-on-primary根据主色亮度自动切换黑白（lightness>65时用深色文字）。
[P][List Bullet] 语义化标签：
[P][Normal] 关键交互元素添加aria-label属性（如"记一笔"按钮、"删除账单"按钮），辅助屏幕阅读器识别元素功能。
[P][List Bullet] 降级方案：
[P][Normal] 毛玻璃效果backdrop-filter在低端设备上可能不生效，已提供纯色半透明背景fallback（rgba(255,255,255,0.84)）。CSS动画在不支持的设备上静默降级，不影响功能。
